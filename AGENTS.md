# Ferron abuse protection

- `crates/abuse-core` owns the Ferron-independent ban policy and unmatched-banned audit records.
- `crates/ferron-abuse-protection` adapts Ferron requests, stages, configuration, and log writers.
- Global `ipban_mode` can operate without definition/ban settings. Its feed is fetched in the background into a bounded, immutable, shared IP set; successful updates replace the set, failures retain the last good set. The definitions allowlist, if loaded, wins over ipban; ipban runs before extban. `ipban_log` uses the existing best-effort bounded Apache-format writer.
- `proxied_by cloudflare` is a global adapter directive. At startup, `cloudflare.rs` loads Cloudflare's IPv4 and IPv6 CIDRs; its stage runs before `ferron_abuse_protection` and trusts `CF-Connecting-IP` only for peers in those ranges. Keep ban/allowlist decisions on the resolved visitor IP, and preserve the connecting peer only for `proxy_ip` logging.
- The default `proxied_by none` uses Ferron's existing `remote_address` behavior. Never accept proxy headers from an untrusted peer or silently continue with the shared Cloudflare peer when its visitor header is invalid.
- When global `ban_mode`, `honeypot_mode`, or `ipban_mode` is enabled, `config_adapter.rs` adds an empty default HTTP host to ports that lack one. This gives unmatched/IP Host requests a resolver layer where global protection runs; do not override configured named-host settings.
- For definition updates, including migration-version updates, do not modify `integration.rs` unless the existing integration harness genuinely cannot exercise the change. The integration test must discover the applicable snapshot YAML, build the test described by that snapshot, and run it; do not add each migration or definition version as a new hard-coded case in `integration.rs`.
- Definition artifacts are generated into the git-ignored `zip/` directory. Build `zip/definitions.sqlite` from scratch with `rm -f zip/definitions.sqlite && sqlite3 -bail zip/definitions.sqlite '.read docs/database/attack-definitions-snapshot-v1.sql'`. Validate it with `cargo run -q -p ferron-abuse-protection --bin abuse-definitions-init -- zip/definitions.sqlite`. Then build `zip/attack-def.zip` containing `definitions.sqlite` and `honeypot-responses/` at the ZIP root; stage copies in a scratch directory before `zip` so entries carry no `../` prefix. Regenerate both artifacts whenever the canonical snapshot or a response template changes.
- Validate changes with `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, and `cargo test --workspace`.
